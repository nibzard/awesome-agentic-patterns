## The Four-Stage Pyramid

An agent change ships safely when each stage of the pyramid only has to catch what the stage below it already ruled out. Skip a stage and the one above drowns.

| Stage                              | Patterns                                                                                                                                                                                                                                                                                                                                                                 | Question It Answers                                                          | Speed and Cost                                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 1. Deterministic checks            | [Structured Output Specification](/patterns/structured-output-specification), [Rich Feedback Loops](/patterns/rich-feedback-loops), [Deterministic Grader in the Loop](/patterns/deterministic-grader-in-the-loop), [Rendered UI Finish Gate](/patterns/rendered-ui-finish-gate)                                                                                         | Does the output have the shape and the properties you can count?             | Schema and counted checks cost no tokens. | 2. Replays cost nothing and need no key            |
| 3. Grader and rubric evals         | [Skill Activation as Precision/Recall Measurement](/patterns/skill-activation-as-precision-recall), [Evidence-Layered Evaluation for Interactive Agents](/patterns/evidence-layered-evaluation-for-interactive-agents), [Output Verification Loop](/patterns/output-verification-loop), [Anti-Reward-Hacking Grader Design](/patterns/anti-reward-hacking-grader-design) | Is the behavior good, not only valid?                                        | Model calls per row, plus labelling and instrumentation time                                  |

### Stage 1: Deterministic Checks

Start with what a machine can verify without a model in the loop.

- [Structured Output Specification](/patterns/structured-output-specification) constrains output with schemas, so a parser or a downstream system can rely on it
- [Rich Feedback Loops](/patterns/rich-feedback-loops) returns compiler errors, test failures, and lint output after each tool call, so the agent has something specific to fix
- [Deterministic Grader in the Loop](/patterns/deterministic-grader-in-the-loop) replaces the LLM-as-judge in a self-review loop with a scorer that returns the raw counts behind each sub-score. It is reproducible, so you can assert it in a test or a CI gate
- [Rendered UI Finish Gate](/patterns/rendered-ui-finish-gate) checks an agent-built interface against its design contract, required states, and rendered output before merge

### Stage 2: Mocked-Tool and Replay CI

Then test the pieces together, with no side effects and no bill.

- [Workflow Evals with Mocked Tools](/patterns/workflow-evals-with-mocked-tools) runs the complete workflow against mocked tools in CI. It checks which tools were called, plus agent-as-judge quality criteria
- [Out-of-Process Provider-Boundary Replay](/patterns/out-of-process-provider-boundary-replay) captures a run at the model-provider HTTP boundary from outside the process, then serves those bytes back. The agent re-executes its own logic with no provider call, so replays belong in CI and in bug reports

Know the limit of replay: blocking provider egress is not sandboxing. The agent still executes its recorded tool calls for real.

### Stage 3: Grader and Rubric Evals

Now ask whether the behavior is good.

- [Skill Activation as Precision/Recall Measurement](/patterns/skill-activation-as-precision-recall) treats skill routing as classification over a labelled dataset, with per-skill precision and recall and CI thresholds that fail the build
- [Evidence-Layered Evaluation for Interactive Agents](/patterns/evidence-layered-evaluation-for-interactive-agents) scores interactive runs on a task outcome assertion and links each result to layered evidence: actions, screenshots, replays, network, and messages
- [Output Verification Loop](/patterns/output-verification-loop) extracts individual claims, checks each against evidence sources, and returns per-claim trust scores before anything acts on the result
- [Anti-Reward-Hacking Grader Design](/patterns/anti-reward-hacking-grader-design) hardens any grader a model optimizes against, with multi-criteria evaluation and iterative hardening

### Stage 4: Production Feedback and Rollout

Finally, let production tell you what the suite missed.

- [LLM Observability](/patterns/llm-observability) gives span-level traces of each model call and tool use, plus aggregate cost, latency, and success metrics
- [Incident-to-Eval Synthesis](/patterns/incident-to-eval-synthesis) converts each production incident into executable eval cases with pass/fail criteria, and gates future releases on them
- [Canary Rollout and Automatic Rollback for Agent Policy Changes](/patterns/canary-rollout-and-automatic-rollback-for-agent-policy-changes) ships a policy change to a small traffic slice, monitors guardrail metrics, and rolls back to the last stable version automatically

## Anti-Patterns

### LLM-as-judge with no deterministic checks underneath

An LLM judge is non-deterministic, costs tokens, and gives the agent nothing specific to fix. [Deterministic Grader in the Loop](/patterns/deterministic-grader-in-the-loop) exists because of this: it replaces the judge with a scorer that returns raw counts, which gives the revision loop a gradient. Reserve the judge for attributes that genuinely need semantic judgment, such as factual correctness or tone for an audience. [Workflow Evals with Mocked Tools](/patterns/workflow-evals-with-mocked-tools) points at the same problem: judge-based results are too variable to serve as a blocking CI gate.

### Testing only the happy path

A suite that checks only the expected output passes on the day before the incident. Three patterns widen it:

- [Rendered UI Finish Gate](/patterns/rendered-ui-finish-gate) keeps required states visible: async, empty, error, and responsive
- [Skill Activation as Precision/Recall Measurement](/patterns/skill-activation-as-precision-recall) scores every skill on every row, so a description edit cannot quietly re-route another skill's prompts
- [Incident-to-Eval Synthesis](/patterns/incident-to-eval-synthesis) turns each real failure into a case

### Letting graders get reward-hacked

Any metric an agent can read, it will learn to satisfy. The deterministic grader pattern calls this Goodhart risk "real and direct" and advises capping the iterations and keeping the threshold well below the maximum. [Anti-Reward-Hacking Grader Design](/patterns/anti-reward-hacking-grader-design) is written for reinforcement learning reward design, and lists "training reward rises while real performance does not" as its warning signal. The same failure appears whenever an agent optimizes against any grader. You cannot harden a grader you never inspect, so traces from [LLM Observability](/patterns/llm-observability) are part of the fix.

### Never turning production bugs into regression cases

An operational fix without an eval case is a promise to debug the same thing twice. [Incident-to-Eval Synthesis](/patterns/incident-to-eval-synthesis) names the symptom: incidents recur after they were fixed operationally, and the eval suite drifts away from what production shows. When a regression slips past the suite anyway, [Canary Rollout and Automatic Rollback](/patterns/canary-rollout-and-automatic-rollback-for-agent-policy-changes) is the last line. It limits the blast radius and shortens time-to-recovery.

## Close the Loop

The stages form a cycle, not a ladder. Production incidents become eval cases at stage 3. Those cases gate releases, and the next policy change ships behind a canary. Each turn of the cycle moves a failure from "surprised us in production" to "fails a PR check".

A minimum loop for a new agent:

1. Constrain the output with a schema
2. Feed compiler, test, and lint output back after each tool call
3. Run a mocked-tool workflow eval on every PR, non-blocking at first
4. Capture traces at the provider boundary, so every bug report is replayable
5. Instrument production
6. Turn each incident into an eval case
7. Ship policy changes behind a canary with automatic rollback
